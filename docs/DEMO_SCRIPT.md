# Five-minute viva demonstration

Before the session, run `npm install`, `npm test`, and `npm run build`. Start `npm run dev` and open the printed local URL. Keep this script and [TEST_REPORT.md](TEST_REPORT.md) available. No API key or network service is needed for the main demonstration.

For an optional rehearsal, leave the dev server running and execute `npm run test:browser` in another terminal. The suite checks real interactions and saves screenshots in `docs/screenshots/`. It uses installed macOS Chrome when available, otherwise Playwright Chromium. If needed, run `npx playwright install chromium` first. `LOGI_CHROME_PATH` selects a browser executable; `LOGI_URL` selects a different local server address. Avoid running the rehearsal while presenting because it opens an automated browser session.

## 0:00–0:35 · Introduce the compiler and verify one result

Load **The LogicHDL example** from Samples.

Say: “Logi-Compile compiles a small hardware description language into executable truth tables, an SVG circuit and Verilog. The compiler is hand-written TypeScript and runs locally. Each stage returns inspectable data.”

Point to `out = (a AND b) OR NOT c;`, then open Codegen → Truth Table. Explain that inputs are in declaration order, with a as MSB. Check `000 → 1`, `001 → 0`, and `111 → 1` aloud. `001` is zero because both `a AND b` and `NOT c` are zero. Point to `Σm(0,2,4,6,7)`.

## 0:35–1:20 · Show the front end thinking

Open Lexer. Select the `AND` token and show its editor span, token type, line and column. Select an input name in the editor to show the corresponding token relation.

Open Parser and switch between the concrete Parse Tree and AST. Say: “The concrete tree preserves grammar rules and punctuation. The AST keeps the program's meaning: declarations, assignments and Boolean operations.” Select the OR node and show its source span.

Enable step-through mode, step twice, then play briefly and change speed. Pause and return to the complete result. Explain that this reveals the actual token/tree result incrementally for teaching; it does not change compilation semantics.

## 1:20–2:00 · Semantics, dependencies and intermediate code

Open Semantic. Point to input/output kinds, declaration and assignment locations, driver expressions and usage counts. Show the dependency graph.

Open IR. Read the real three-address instructions:

```text
t1  = AND a, b
t2  = NOT c
out = OR t1, t2
```

Point out the netlist gate IDs. Select a TAC row, then inspect the highlighted circuit gate. Say: “Signal dependency order, rather than source statement order, determines evaluation. Copies are connections and do not count as gates.”

## 2:00–2:45 · Prove optimization preserves behavior

Load **Optimization playground**. Open Optimizer.

Point to identity removal such as `a AND 1 → a`, double negation, common subexpression elimination and dead-code removal. Compare the original and optimized diagrams, gate counts and depths. Select a rewrite to jump to its source span.

Say: “The optimizer is local Boolean simplification plus netlist CSE and reachability-based dead-code removal. It is not a claim of globally minimal synthesis.”

Point to **Equivalence verified** and the checked-row count. Explain that all output bits are compared on every input combination. Turn optimization off and show the larger original target; turn it on again. A test with deliberately nonequivalent netlists proves the checker can return a counterexample.

## 2:45–3:35 · Demonstrate lexical, syntax and semantic errors

Use three broken samples quickly:

1. **Illegal characters**: show both scanner errors and retained tokens. Click a diagnostic to jump to the editor. Point out that later stages are blocked by Lexer.
2. **Syntax recovery**: show the missing operand and empty-group errors from separate statements. Open Parser to show its partial concrete tree. Explain synchronization at semicolons.
3. **Combinational cycle**: show the full cycle path in the semantic diagnostic. Open the dependency graph. State that the language models combinational hardware, so a feedback latch requires a different language feature.

If an examiner asks for another category, load **Multiple drivers**, **Undefined signal**, **Signal never assigned**, **Keyword used as a name**, or **Truth table input limit**. Multiple drivers include both source locations.

## 3:35–4:20 · Simulate a useful circuit and export it

Load **Full adder**. Open Simulator. Set `a = 1`, `b = 1`, `cin = 0`; show `sum = 0`, `cout = 1`. Set cin to 1; show `sum = 1`, `cout = 1`. Trace a green high net and a grey low net. Show the live matching truth-table row.

Open Verilog and show the continuous assign statements. Copy it. Export a truth-table CSV or circuit SVG. Point out that the diagram is generated by the project's own layered-layout algorithm and uses standard gate outlines and inversion bubbles.

## 4:20–5:00 · Evidence, design choices and close

Show the six-stage pipeline and briefly switch light/dark mode or resize the window. Copy a share link and mention that the URL hash contains the source.

Open the repository or test report. Say: “Tests cover each phase, all working samples against separate reference equations, exact diagnostic locations, two hundred seeded random expression equivalence checks, and garbage/extreme inputs. The pure compiler has no React or DOM dependency.”

Point to `docs/AI_USAGE_LOG.md` and `docs/PROMPTS.md` as the AI Product Engineering process evidence. If a key is available and time permits, show **Explain this error** or English-to-LogicHDL. For an unscoped key, enter the required workspace ID in the assistant's optional field before the demo; workspace-scoped keys can omit it. Use the editable model field if the account requires another supported model. Explain that generated code always passes through this deterministic compiler, including one correction retry; AI is optional and never decides compiler correctness. Close the drawer to discard entered credentials.

State the limits directly: “This is a single-bit combinational language with twelve inputs maximum so exhaustive checking stays bounded. It has no state, clocks or industrial timing analysis.”

## Questions to prepare for

| Question | Answer to demonstrate |
| --- | --- |
| Why is `a NAND b NAND c` not flattened? | NAND is not associative. The AST preserves left association. |
| How do forward references work? | Collect declarations first, build dependencies, then topologically order drivers. |
| What is the difference between a wire and a temporary? | A wire is a declared named signal; a temporary is compiler-generated. Both can identify nets. |
| Why is a COPY instruction not a gate? | It names the same electrical value; it adds no Boolean operation or logic depth. |
| What happens after an error? | Earlier phase artifacts remain; later phases record the first blocking phase. |
| Does the equivalence badge prove global minimality? | It proves matching outputs for every bounded input assignment, not minimal gate count. |
| Why twelve inputs? | Truth-table and equivalence costs grow exponentially; twelve caps them at 4,096 rows. |
| Can it make an SR latch? | The feed-forward sample computes next-state logic from external q_in. Feedback storage is rejected. |
| How is the diagram drawn? | Rank gates by depth, order by upstream vertical positions, separate boxes, route orthogonal polylines, serialize SVG. |
| What did AI do? | Generate implementation and tests under recorded tasks; agent review and automated checks are documented, without claiming independent human review. |
